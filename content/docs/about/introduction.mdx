lla is a command-line file lister. Run it wherever you'd run `ls`. It's a single binary, and it works without any configuration.

<Shot name="view-default" alt="The default lla view, listing a repository's files and directories with icons." caption="`lla` in a checkout of its own repository, with icons turned on." />

## What it adds to ls

`ls` tells you what's in a directory. lla also answers the questions you usually open a second tool for.

| You want to know | Run |
| --- | --- |
| How is this project laid out? | `lla -t -d 3` |
| What changed, and who last touched it? | `lla -G` |
| What did I work on recently? | `lla --timeline` |
| Where did the disk space go? | `lla -S --include-dirs` |
| What can I delete to free up space? | `lla scan` |
| Which files mention this? | `lla --search "TODO"` |
| How does this differ from the last commit? | `lla diff src --git` |
| What's inside this archive? | `lla backup.tar.gz -t` |
| Where is that file I was editing? | `lla -F` |
| Which file has this line in it? | `lla --contents` |
| Can a script read this? | `lla --json` |

## Views

A view changes how a listing is drawn. Filters and sorting carry over, so you can narrow a selection first and then look at it in different ways.

<ViewIndex />

[Views](/docs/usage/views) shows each one with a screenshot. For opening and acting on files interactively, use the [fuzzy view](/docs/usage/navigation#fuzzy-view).

## Disk cleanup

`lla scan` goes through your home folder and sorts what it finds into apps, developer files, caches, logs, downloads, media and trash. Each item is labeled safe to clean, review first, or your files, and you can move what you don't need to the trash from the same screen. See [Disk scan](/docs/usage/disk-scan).

## Selecting and searching

You can select entries by name, regular expression, size, date, type or `.gitignore` status, and save a combination you use often as a preset. `lla --search` runs ripgrep over file contents and prints highlighted matches with surrounding lines. See [Filtering and search](/docs/usage/filtering-search).

## Plugins

Plugins add columns to listings and commands to lla. The project maintains [37 of them](/docs/first-party-plugins/overview), including file hashes, code complexity, security audits and terminal previews. You can install them all with one command and turn on only the ones you want.

<Shot name="plugin-manager" alt="The interactive plugin manager, a checklist of installed plugins with their versions." caption="`lla use` turns plugins on and off." />

Native plugins run inside the lla process and are fully trusted. WebAssembly plugins run in a sandbox and can only use the access you grant them. [Plugins](/docs/plugins/overview) explains the difference.

## Scripts

`--json`, `--ndjson` and `--csv` print the same selection with a fixed set of fields, so lla can feed `jq`, a spreadsheet or a build step. See [Machine output](/docs/usage/machine-output).

## Platforms

lla runs on Linux, macOS, NetBSD and Windows 10 or later. Static musl builds on Linux and the NetBSD build have fewer plugin options; [Installation](/docs/about/installation#platform-notes) has the details.
