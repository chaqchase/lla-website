Each heading is a symptom. Under it you'll find the cause and the fix, checked against lla 0.6.6.

## Install and config

### `lla: command not found`

Cause: the directory holding the binary isn't on your `PATH`. The install script uses `/usr/local/bin`, and `cargo install` uses `~/.cargo/bin`.

Fix: add the directory to your `PATH` in your shell's startup file.

```bash
export PATH="$HOME/.cargo/bin:$PATH"
```

### `Warning: TOML parse error` on every run

```text
Warning: TOML parse error at line 1, column 1
  |
1 | theme = "nord"
  | ^^^^^^^^^^^^^^
missing field `default_sort`
```

Cause: `~/.config/lla/config.toml` is invalid or incomplete, so lla ignores the whole file and uses built-in defaults. A global config must include every required key, so a hand-written file with a few settings fails. A `"` in a shortcut description or a `.` in a shortcut name also causes this.

Fix: correct the line the warning points to. To start over, move the file aside and run `lla`, which writes a new one. Then change settings with `lla config --set`. A project's `.lla.toml` can be partial.

```bash
mv ~/.config/lla/config.toml ~/.config/lla/config.toml.bak
lla
```

## Listings

### A filter with capital letters returns nothing

Cause: filtering lowercases file names but leaves your pattern as written, so `README` is compared with `readme.md`. This affects `-f`, `glob:` and `regex:` patterns, and `--refine`.

Fix: write the pattern in lowercase, as in `lla -f readme`, or add `-c` to match exact case, as in `lla -f README -c`.

### A filter for several extensions returns nothing

Cause: comma lists and brace globs don't work for extensions in 0.6.6.

Fix: use `OR`, and quote the pattern.

```bash
lla -f ".rs OR .toml"
```

### `--modified` returns the opposite of what you expected

Cause: the comparison runs in reverse. `<7d` selects entries older than 7 days. `--created` works the same way.

Fix: use `>` for recent entries.

```bash
lla --modified ">7d"    # changed within the last 7 days
lla --modified "<7d"    # older than 7 days
```

### Dotfiles are missing from a tree or recursive listing

Cause: `-t` and `-R` skip dot-named files, even with `-a`. Dot-named directories still appear.

Fix: list them with a flat view: `lla --dotfiles-only`.

### A tree or recursive listing stops early

Cause: depth defaults to `default_depth`, which starts at 3. Separately, `listers.recursive.max_entries` caps both views at 20000 files, and lla stops there without a warning.

Fix: raise the depth or the limit.

```bash
lla -t -d 6
lla config --set listers.recursive.max_entries 50000
```

### Icons show as squares or question marks

Cause: lla's icons use Nerd Font glyphs, and your terminal font doesn't have them.

Fix: install a font from [nerdfonts.com](https://www.nerdfonts.com/) and select it in your terminal, or turn icons off with `lla config --set show_icons false`.

## Git view

### `Not a git repository` for a subdirectory of a repository

Cause: `lla -G src` fails because a relative path with no `./` never reaches the repository root.

Fix: start the path with `./`, as in `lla -G ./src`, use an absolute path, or `cd` into the directory.

### A directory shows `[clean]` although a file inside it changed

Cause: Git view reports status for each entry in the listing, and a directory has no status of its own. The header counts do cover the whole repository.

Fix: run `lla -G` inside that directory.

## Search

### `--search` returns nothing with a relative directory

Cause: `lla --search X src` changes into `src` and then looks for paths that still start with `src`. Nothing matches, and lla prints no error.

Fix: run search from that directory, or pass an absolute path.

```bash
cd src && lla --search "TODO"
lla --search "TODO" "$PWD/src"
```

### `Failed to run ripgrep`

Cause: `lla --search` runs `rg`, and it isn't on your `PATH`.

Fix: [install ripgrep](https://github.com/BurntSushi/ripgrep#installation), then check with `rg --version`.

### Search returns matches from `.git/`

Cause: search includes dot-named files and directories by default.

Fix: add `--no-dotfiles`, as in `lla --search "TODO" --no-dotfiles`.

### `-f` doesn't narrow search results

Cause: lla gives ripgrep an explicit list of files, and `-f` doesn't filter that list in 0.6.6.

Fix: search from a narrower directory, or run ripgrep directly with `rg "TODO" --glob "*.rs"`.

## Fuzzy view and jump

### Fuzzy view stays at "Indexing files"

`lla -F` shows `Indexing files... 0 files found` and the list never fills.

Cause: the default file indexer doesn't finish in 0.6.6. The indexer used for gitignore filtering does.

Fix: press Esc, then add `--respect-gitignore`, or make it your default. The setting also hides ignored files in every other view. See [Fuzzy view](/docs/usage/navigation#fuzzy-view) for the keys.

```bash
lla -F --respect-gitignore
lla config --set filter.respect_gitignore true
```

### `lla jump` prints a path but your directory doesn't change

Cause: a program can't change its parent shell's directory, so `lla jump` only prints the path you pick.

Fix: run `lla jump --setup`, open a new terminal, and use `j` instead. See [Jump](/docs/usage/navigation#jump).

### `interactive mode error: IO error: not a terminal`

Cause: `lla jump` needs a terminal for its selector. A script or redirected input doesn't provide one.

Fix: run it from an interactive shell. In a script, read paths with `lla jump --list`.

## Themes

### `Theme 'nord' not found`

```text
✗ Error

  Theme 'nord' not found. Install it with `lla theme pull` or place it in ~/.config/lla/themes
```

Cause: `lla theme preview` and `lla config --set theme` only see installed themes. A new install has none, and `default` only appears after you run `lla init`.

Fix: pull the official themes, then preview again. `lla theme pull` clones the lla repository, so it needs Git and network access. Without those, run `lla theme install <path>` on a theme file or directory you already have.

```bash
lla theme pull
lla theme preview nord
```

## Plugins

### `Plugin 'NAME' not found`

Cause: the plugin isn't installed in any directory lla searches, or the name is misspelled.

Fix: check `lla list-plugins`, then run `lla install` to add what's missing.

### `Plugin 'NAME' was disabled. Enabling it now...`

Cause: you ran an action or shortcut for a disabled plugin. lla turned it on and saved that to your config, so its output now appears in your listings.

Fix: turn it off when you're done with `lla --disable-plugin NAME`.

### `Action 'NAME:ACTION' is interactive and requires a TTY with --output human`

Cause: the plugin declares this action as interactive, so it can't run in a pipe, a script, or with `--output json`.

Fix: run it directly in a terminal.

### `warning: 'lla plugin <plugin> <action>' is deprecated`

Cause: you used the old form. lla 0.6.6 also prints this warning for every shortcut. It goes to stderr and the action still runs.

Fix: in scripts, use the current form, as in `lla plugin run project_context inspect -- .`.

### `Plugin PATH uses API v1 and is disabled; migrate it to API v3`

Cause: lla 0.6 only loads API v3 plugins.

Fix: migrate official plugins with the commands below. Third-party plugins have to be rebuilt against `lla_plugin_sdk` 0.6. See [Migrating to v3](/docs/plugins/migration-v3).

```bash
lla plugin migrate --prebuilt
lla plugin doctor
```

### A plugin fails `lla plugin doctor`

Cause: its checksums or contract don't match, or the package is damaged.

Fix: run `lla clean`, then `lla install`. `lla clean` moves invalid plugins to `.quarantine/<timestamp>/` inside the plugins directory, so you can recover them.

### `Dynamic plugins are unavailable in this build`

Cause: static musl builds can't load plugins.

Fix: install a GNU build. See [Installation](/docs/about/installation).

## Report a bug

Search the [GitHub issues](https://github.com/chaqchase/lla/issues) first. If it's new, open an issue with your operating system, the command you ran, what you expected, and what happened, along with the output of these commands:

```bash
lla --version
lla config diff --default
lla plugin doctor
```
