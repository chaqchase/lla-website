`flush_dns` runs your system's DNS flush commands and keeps a history of each flush. Reach for it after a DNS change that hasn't reached your machine, when you don't want to look up the command for your OS. It adds nothing to listings.

## Actions

Run an action with `lla plugin run flush_dns <action>`. Every action is interactive, so it needs a TTY and the default `--output human`.

| Action | What it does |
| --- | --- |
| `flush` | Flushes the DNS cache, after a confirmation that defaults to yes. |
| `history` | Prints the latest 20 flushes and the counts. |
| `clear-history` | Clears the history, after a confirmation that defaults to no. |
| `preferences` | Opens a menu for the settings below. |
| `help` | Prints usage. |

`flush` runs these commands:

| System | Commands |
| --- | --- |
| macOS | `sudo dscacheutil -flushcache`, then `sudo killall -HUP mDNSResponder` |
| Linux | `sudo systemd-resolve --flush-caches`, falling back to `sudo systemctl restart nscd` |
| Windows | `ipconfig /flushdns` |

`sudo` may ask for your password.

## Example

```bash
lla plugin run flush_dns history
```

```text
Info: No flush history available
```

## Settings

The plugin reads `~/.config/lla/plugins/flush_dns/config.toml`, which also stores the history as `flush_history`.

```toml
confirm_before_flush = true
show_verbose_output = true
max_history_size = 50
```

A `[colors]` table sets `success`, `info`, `warning` and `error`.

## Permissions

`process = true`, because it runs the flush commands above.
