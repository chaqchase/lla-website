`file_remover` deletes files and directories you pick from a multi-select prompt. `remove` moves them to the recoverable [trash](/docs/first-party-plugins/trash), and `purge` deletes them for good. Reach for it when you want to clear several items from one directory and see each one before it goes. It adds nothing to listings.

## Actions

Run an action with `lla plugin run file_remover <action> -- <args>`. Every action is interactive, so it needs a TTY and the default `--output human`.

| Action | Arguments | What it does |
| --- | --- | --- |
| `remove` | `[dir]` | Moves selected items to the trash after a confirmation. |
| `purge` | `[dir]` | Permanently deletes selected items after a confirmation. |
| `help` | | Prints usage. |

Both actions list one directory level, the current directory if you name none. The confirmation defaults to no.

<Callout type="warning">
`purge` can't be undone. Trashed items are recoverable, so prefer `remove`.
</Callout>

## Example

```bash
lla plugin run file_remover remove -- ~/project/rm
```

```text
Warning: The following items will be moved to trash:
  → r3.txt
Move these items to recoverable trash? yes
Success: Trashed: ~/project/rm/r3.txt (id: 20261104T225943.213Z-27293-0)

Summary: Operation completed: 1 items trashed, 0 errors
```

Trashed items go to `~/.config/lla/plugins/trash/`. Find the ID and restore with the `trash` plugin.

```bash
lla plugin run trash list
lla plugin run trash restore -- 20261104T225943.213Z-27293-0
```

```text
20261104T225943.213Z-27293-0  2026-11-04T22:59:43Z  3 bytes  ~/project/rm/r3.txt
Restored to ~/project/rm/r3.txt
```

## Permissions

`filesystem = ["read:tree", "write:user-path", "delete:selection", "delete:quarantine"]`: it deletes what you select and moves trashed items into the shared trash store.
