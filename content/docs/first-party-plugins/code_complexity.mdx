`code_complexity` adds a complexity score and maintainability index to each source file, plus line, function, branch and loop counts and suggestions in the long view. Turn it on for a first look at which files in a directory carry the most branching. It matches patterns line by line and doesn't parse code, and it covers Rust until you add other languages.

<Shot name="plugin-code-complexity" alt="A long listing in which each Rust file shows its complexity, maintainability index, line, function, branch and loop counts, and suggestions." caption="`lla -l --hide-group <dir>` with only `code_complexity` enabled." />

## Turn it on

```toml
# ~/.config/lla/config.toml
enabled_plugins = ["code_complexity"]
```

Or run this once. It saves the same setting, so the plugin stays on until you run `lla --disable-plugin code_complexity`.

```bash
lla --enable-plugin code_complexity
```

Output appears in the default and long views (`formats = ["default", "long"]`), and in the table view, which uses the long format. The default view shows only the `Complexity` row.

The plugin adds one field, `complexity_metrics`, a string holding the numbers as TOML. Read it as JSON:

```bash
lla --json src | jq -r '.[] | select(.name=="main.rs") | .plugin.complexity_metrics'
```

```text
lines = 29
functions = 3
classes = 2
branches = 2
loops = 1
comments = 5
long_lines = 0
long_functions = []
cyclomatic_complexity = 3
cognitive_complexity = 12
maintainability_index = 52.561866760253906
```

## Actions

Run an action with `lla plugin run code_complexity <action> -- <args>`. Every action is interactive, so it needs a TTY and the default `--output human`. Running one also enables the plugin and saves that setting.

| Action | Arguments | What it does |
| --- | --- | --- |
| `set-thresholds` | `<low> <medium> <high> <very_high>` | Saves new thresholds to the settings file, creating it if needed. |
| `show-report` | | Prints a heading with no data in 0.6.6, because statistics don't carry over between runs. |
| `help` | | Prints usage. |

```bash
lla plugin run code_complexity set-thresholds -- 10 20 30 40
```

## Example

The number after `Complexity` is the cyclomatic count, and `MI` is the maintainability index.

```bash
lla -l --hide-group
```

## Settings

The plugin reads `code_complexity.toml` from your system's config directory: `~/Library/Application Support/lla/` on macOS and `~/.config/lla/` on Linux. It ignores `~/.config/lla/plugins/code_complexity/config.toml`.

The file doesn't exist until you create it or run `set-thresholds`. To analyze another language, run `set-thresholds` first so the file holds the Rust rules, then add a table. A hand-written file replaces the built-in Rust rules, and each language needs all of these keys.

```toml
[languages.Python]
extensions = ["py"]
function_patterns = ["def "]
class_patterns = ["class "]
branch_patterns = ["if ", "elif ", "else"]
loop_patterns = ["for ", "while "]
comment_patterns = ["#"]
max_line_length = 100
max_function_lines = 50
```

`[thresholds]` holds `low`, `medium`, `high` and `very_high`, and `[colors]` holds a color for each. They set the color of the `Complexity` label and leave the numbers alone. The plugin computes `cyclomatic * 0.4 + cognitive * 0.3 + (100 - MI) * 0.3` and picks the first level the result is under. At or above `high` it uses the `very_high` color, so the `very_high` number has no effect.
