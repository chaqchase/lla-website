A view changes how a listing is drawn. It doesn't change what's selected, so you can combine any view below with the [filters and sorting](/docs/usage/filtering-search).

<ViewIndex />

To stop passing a flag every time, set your usual view with [`default_format`](/docs/usage/configuration#defaults).

## Default view

Names only, one per line. This is the view to use for a quick look.

```bash
lla
lla src
lla src docs
```

Give several paths and each directory is listed under its own `path:` heading, the way `ls` does it. A path that can't be listed is reported and the rest are still shown, with exit status 1.

<Shot name="view-default" alt="The default view, a plain list of file and directory names with icons." caption="`lla`" />

## Long view

Permissions, size, modification date, owner and group, plus any metadata you ask for. Use it when the details of each file matter.

```bash
lla -l
lla -l --hide-group --relative-dates
lla -l --date-format "%Y-%m-%d %H:%M"
lla -l --permission-format octal
```

<Shot name="view-long" alt="The long view, with permissions, size, date, owner and group columns beside each name." caption="`lla -l`" />

These flags add more metadata:

| Flag | Adds |
| --- | --- |
| `-i`, `--inode` | Inode number |
| `-H`, `--links` | Hard-link count |
| `--allocated-size` | Disk space actually allocated |
| `-@`, `--extended` | Extended attribute names and sizes |
| `-Z`, `--context` | ACL or SELinux context |
| `-M`, `--mounts` | Mount source, mount point and filesystem |
| `--include-dirs` | Recursive directory sizes, which can be slow on large trees |

Symlinks show their target after the name. `--no-symlink-target` hides it, and `-X`, `--dereference` reports the target's metadata instead of the link's.

`--permission-format` accepts `symbolic`, `octal`, `binary`, `verbose` or `compact`.

<Shot name="long-octal" alt="The long view with octal permissions and relative dates." caption="`lla -l --permission-format octal --relative-dates --hide-group lla/src/formatter`" />

### Choose the columns

Set the columns and their order in your config:

```toml
[formatters.long]
hide_group = true
relative_dates = true
date_format = "%Y-%m-%d %H:%M"
columns = ["permissions", "size", "modified", "name", "field:git_status"]
```

The built-in keys are `permissions`, `inode`, `links`, `size`, `allocated`, `modified`, `created`, `accessed`, `user`, `group`, `xattrs`, `context`, `mount`, `name`, `path` and `plugins`. Use `field:<name>` for a field added by a plugin.

## Tree view

The directory hierarchy, to the depth you choose. The default depth is 3, and `default_depth` in your config changes it.

```bash
lla -t
lla -t -d 2 docs
lla -t --sort size
```

Tree and recursive views follow `--sort`, `--sort-reverse` and `--sort-dirs-first`, with the name breaking ties. They show dotfiles unless you pass `--no-dotfiles`, and they list `.git` without going into it. Both stay fast on big trees: 40,000 entries take about 60 ms.

<Shot name="view-tree" alt="The tree view, with nested directories drawn using branch lines." caption="`lla -t -d 2 docs`" />

## Table view

The long view's data in aligned, bordered columns. It's easier to scan down a single column, which helps when you're comparing files.

```bash
lla -T
```

<Shot name="view-table" alt="The table view, with bordered columns for permissions, size, date and name." caption="`lla -T lla/src/formatter`" />

It takes the same column keys as the long view:

```toml
[formatters.table]
columns = ["permissions", "size", "modified", "name"]
```

## Grid view

Names in as many columns as your terminal fits, filled top to bottom. Each column is only as wide as its longest name, so one long name doesn't push everything into a single column. Use it for directories with many short names.

```bash
lla -g
lla -g --grid-ignore
```

`--grid-ignore` ignores the terminal width, so lines can run off the screen.

<Shot name="view-grid" alt="The grid view, with theme file names arranged in several columns." caption="`lla -g themes`" />

## Git view

Each entry's Git status with its last commit, subject, age and author. A header shows the branch, its upstream, and how many files are staged or changed. Run it anywhere inside a repository, or pass a subdirectory. It runs a fixed number of Git commands however many files there are, so a 1,000-file repository takes about 50 ms.

```bash
lla -G
lla -G src
```

<Shot name="view-git" alt="The Git view, with a status column and last-commit details for each entry." caption="`lla -G`" />

## Timeline view

Entries grouped by when they last changed: today, yesterday, last week, last month and older. Use it to find what you were working on.

```bash
lla --timeline
```

<Shot name="view-timeline" alt="The timeline view, with files grouped under time-period headings." caption="`lla --timeline lla/src`" />

## Size map view

Bars that compare entries by size, each with its share of the total. Add `--include-dirs` to count directories as well, which walks them recursively.

```bash
lla -S
lla -S --include-dirs
```

<Shot name="view-sizemap" alt="The size map view, with proportional bars next to each file." caption="`lla -S lla/src/formatter`" />

## Recursive view

Every nested directory, as a flat listing grouped by directory. `-d` limits the depth. To cap very large walks, set [`max_entries`](/docs/usage/configuration#limits).

```bash
lla -R
lla -R -d 2
lla -R -l
```

<Shot name="view-recursive" alt="The recursive view, listing each directory's files under a path heading." caption="`lla -R -d 2 sdk`" />

## Archives

lla reads `.zip`, `.tar`, `.tar.gz` and `.tgz` files as if they were directories, without extracting them. Views, filters and machine output all work.

```bash
lla backup.tar.gz -t
lla project.zip -l -f ".rs"
lla bundle.tgz --json
```

<Shot name="archive" alt="A tree view of the contents of a tar.gz archive." caption="`lla ../docs.tar.gz -t -d 2`" />

## Single files

Pass a file to see only that entry, in any view.

```bash
lla Cargo.toml -l
lla src/main.rs --json
```

## Compare files and directories

`lla diff` compares two paths, or one path against a Git reference.

```bash
lla diff src ../backup/src
lla diff src --git
lla diff src --git --git-ref HEAD~1
lla diff Cargo.lock ../backup/Cargo.lock
lla diff Cargo.lock --git --git-ref HEAD~1
```

`--git` compares against `HEAD` unless you set `--git-ref`.

For directories, you get each entry's status and size change.

<Shot name="diff-dir" alt="A directory diff, listing added and modified files with size changes." caption="`lla diff lla/src --git`" />

For files, you get the size and line-count changes followed by a unified diff. Binary files are detected and their content isn't printed.

<Shot name="diff-file" alt="A file diff, with a size summary followed by a unified diff." caption="`lla diff lla/src/main.rs --git`" />

## Options for any view

| Option | Effect |
| --- | --- |
| `--icons`, `--no-icons` | Turn icons on or off for this run. Icons from your config are left out when the output is piped, unless you pass `--icons` |
| `--no-color` | Print without color |
| `--hyperlink always\|auto\|never` | Make names clickable with OSC 8 links |
