Filters choose which entries appear in a listing, and they work with every view. To find text inside files, use [content search](#search-file-contents), which has its own rules.

<Diagram caption="Each filter narrows the selection, and the view draws what's left."><FilterGates /></Diagram>

## Sort

```bash
lla -s size
lla -s date -r
lla --sort-dirs-first
lla --sort-natural
lla --sort-case-sensitive
```

`-s`, `--sort` takes `name`, `size` or `date`. `-r`, `--sort-reverse` flips the order. `--sort-natural` puts `2.txt` before `10.txt`.

## Filter by name

`-f`, `--filter` matches anywhere in the name.

```bash
lla -f test
lla -f .rs
lla -f "regex:^(cargo|flake|install)"
lla -f "glob:*.toml"
```

<Shot name="filter-regex" alt="A long listing narrowed to names matching a regular expression." caption='`lla -f "regex:^(cargo|flake|install)" -l --hide-group`' />

Write patterns in lowercase. lla lowercases each file name before comparing it to your pattern, but not the pattern itself, so `-f readme` finds `README.md` and `-f README` finds nothing. To match exact case, add `-c`, `--case-sensitive`.

To combine terms, use one of these forms:

| Form | Matches names containing |
| --- | --- |
| `test,spec` | `test` or `spec` |
| `+test,api` | `test` and `api` |
| `"test AND .rs"` | `test` and the `.rs` extension |
| `".toml OR .lock"` | Either extension |
| `"NOT .md"` | Anything except `.md` files |

<Callout type="warning" title="Matching several extensions">
  In lla 0.8.0, `glob:*.{toml,lock}` and `.toml,.lock` both return nothing. Use `".toml OR .lock"` instead.
</Callout>

## Filter by size

```bash
lla --size ">10M"
lla --size "512K..2G"
lla --size "..100K"
```

Sizes take `K`, `M` and `G` suffixes, and ranges can be open at either end.

## Filter by date

`--modified` and `--created` take a relative age or a date range:

```bash
lla --modified ">7d"
lla --modified "<30d"
lla --created "2026-01-01..2026-06-30"
```

<Callout type="warning" title="Read the operator as a point in time">
  `>7d` means after the moment seven days ago, so it selects what changed **in the last week**. `<30d` means before the moment 30 days ago, so it selects what's **older than a month**.
</Callout>

Combine filters to get a precise selection, then sort it:

```bash
lla --files-only --size ">2K" --modified ">30d" -s size -l --hide-group
```

## Filter by type

| Show only | Hide |
| --- | --- |
| `--dirs-only` | `--no-dirs` |
| `--files-only` | `--no-files` |
| `--symlinks-only` | `--no-symlinks` |
| `--dotfiles-only` | `--no-dotfiles` |

`--show-symlinks` also includes symlinks whose targets match `--dirs-only` or `--files-only`. `-a`, `--all` and `-A`, `--almost-all` show dotfiles even if your config hides them.

## Respect .gitignore

`--respect-gitignore` hides anything matched by `.gitignore` or Git's exclude rules. To make that the default, add this to your config:

```toml
[filter]
respect_gitignore = true
```

`--no-gitignore` turns it off again for one run.

## Presets

A preset saves a set of filters under a name. Define it in `~/.config/lla/config.toml`:

```toml
[filter.presets.recent_rust]
description = "Rust files changed in the last week"
filter = ".rs"
modified = ">7d"
```

```bash
lla --preset recent_rust
```

## Refine a listing

`--refine` narrows a listing you've already run. It reads lla's cached copy of that listing instead of walking the directory again. Repeat the flag to narrow further, and an entry must match every refinement to stay.

```bash
lla -l --refine cargo --refine .toml
```

lla caches each directory listing under the directory and options you used. If there's no match in the cache, `--refine` walks the directory first. Because a cached listing can be out of date, run the command without `--refine` to refresh it.

## Search file contents

`--search` runs ripgrep from the current directory. It prints each match with its path, line number, syntax highlighting and two lines of context. Patterns are literal unless you prefix them with `regex:`.

```bash
lla --search "TODO"
lla --search "TODO" --search-context 5
lla --search "regex:^func.*\("
lla --search "Error" --case-sensitive
```

<Shot name="search" alt="Content search results, with highlighted matches and surrounding lines from Rust files." caption='`lla --search "record_visit" --search-context 1`' />

To search another directory, change into it or give an absolute path:

```bash
lla "$(pwd)/src" --search "TODO"
```

<Callout type="warning" title="Relative directories">
  In lla 0.8.0, `lla src --search "TODO"` returns nothing, and passing a relative file path fails. Use an absolute path, as above.
</Callout>

### Which filters apply to search

| Option | During search |
| --- | --- |
| `-c`, `--case-sensitive` | Applied |
| `--no-dotfiles`, `-A` | Applied |
| `--dirs-only`, `--no-files` | Return no results, since ripgrep only reads files |
| `--no-gitignore` | Ignored. Search always applies Git ignore rules |
| `-f`, `--preset`, size, date, `--refine`, other type filters | Ignored |

<Callout type="warning" title="Limiting search to one file type">
  In lla 0.8.0, `lla --search "TODO" -f .rs` still searches every file. Filter the results yourself, for example with `--json` and `jq`.
</Callout>

If your config shows dotfiles, search also reads `.git/`. Add `--no-dotfiles` to skip it.

`exclude_paths` from your config only matches reliably when the search root is absolute.

For `--json`, `--ndjson` and `--csv`, see [search results](/docs/usage/machine-output#search-results).

### Send matches to a plugin

`--search-pipe` runs a plugin action once when the search finishes, adding every matching path to the action's arguments. The form is `plugin:action[:arg...]`. It turns on the plugin if it's off.

```bash
lla --search "setup_shell_integration" --search-pipe preview:show
```

The action has to accept that many paths. `preview show` takes one, so the command above only works when one file matches. Among the official plugins, only `trash put` takes any number of paths, and it moves every match to the trash.
