This tutorial builds `file_score`, a native plugin that adds a size score to each file in a listing and exposes an `inspect` action. You start with an empty directory and finish with `lla plugin doctor` passing.

The code and output below come from a real build on macOS with lla 0.6.6. You need a Rust toolchain and lla installed.

```bash
cargo --version
lla --version
```

## Create the crate

```bash
cargo new --lib file-score
cd file-score
```

Replace `Cargo.toml` with this:

```toml
[package]
name = "file-score"
version = "1.0.0"
edition = "2021"

[lib]
name = "file_score"
crate-type = ["cdylib"]

[dependencies]
lla_plugin_sdk = "0.6"
```

`crate-type = ["cdylib"]` builds the shared library that lla loads. `name = "file_score"` sets the library's filename, and the manifest's `entrypoint` has to match it.

## Write the manifest

Create `plugin.toml` next to `Cargo.toml`. The manifest is the plugin's contract: it says what the plugin adds and which commands it accepts, and lla checks the code against it.

```toml
schema_version = 3

[plugin]
id = "dev.example.file-score"
name = "file_score"
version = "1.0.0"
api_min = 3
api_max = 3
runtime = "native"
entrypoint = "file_score"
description = "Score files by size"

[capabilities]
decorates_entries = true
formats = ["default", "long"]
machine_output = true

[permissions]
filesystem = ["metadata:selection", "read:user-path"]

[[fields]]
name = "score"
type = "integer"
description = "Base-2 logarithm of the file size"

[[fields]]
name = "size_class"
type = "string"
description = "small, medium or large"

[[actions]]
id = "inspect"
description = "Score one file"
examples = ["lla plugin run file_score inspect -- README.md --multiplier 2"]
arguments = [
  { name = "path", type = "path", description = "File to score", position = 0, required = true },
  { name = "multiplier", type = "integer", description = "Multiply the score", option = "--multiplier", default = 1, min = 1, max = 10 },
]
output = { type = "value" }
```

| Section | What it does here |
| --- | --- |
| `[plugin]` | Names the package and declares that it supports host API 3. `entrypoint` is the library name without a platform prefix or suffix. |
| `[capabilities]` | `formats` lists the views that call the plugin: the default listing and `lla -l`. Other views skip it. |
| `[permissions]` | Declares what the plugin touches. Native code runs fully trusted, so `lla plugin info` displays these and nothing enforces them. |
| `[[fields]]` | Declares the typed values the plugin sets on each entry. |
| `[[actions]]` | Declares the `inspect` command, its arguments and its output type. |

The [manifest reference](/docs/plugins/manifest) lists every field and accepted value.

## Write the plugin

Replace `src/lib.rs` with this:

```rust
use lla_plugin_sdk::{
    interface::proto, response, value, ActionArguments, ActionArgumentsExt, DecoratedEntryExt,
    Plugin,
};

#[derive(Default)]
struct FileScore;

fn score(size: u64) -> i64 {
    size.checked_ilog2().unwrap_or(0) as i64
}

fn size_class(size: u64) -> &'static str {
    match size {
        0..=1023 => "small",
        1024..=1_048_575 => "medium",
        _ => "large",
    }
}

impl Plugin for FileScore {
    fn decorate_entry(&mut self, mut entry: proto::DecoratedEntry) -> proto::DecoratedEntry {
        let Some(metadata) = entry.metadata.as_ref() else {
            return entry;
        };
        if !metadata.is_file {
            return entry;
        }
        let size = metadata.size;
        entry.insert_field(
            "score",
            value::integer(score(size)),
            score(size).to_string(),
        );
        entry.insert_field(
            "size_class",
            value::string(size_class(size)),
            size_class(size),
        );
        entry
    }

    fn format_field(&mut self, entry: proto::DecoratedEntry, format: String) -> Option<String> {
        let score = entry.custom_fields.get("score")?;
        let class = entry.custom_fields.get("size_class")?;
        match format.as_str() {
            "default" => Some(format!("[score:{score}]")),
            "long" => Some(format!("score={score} class={class}")),
            _ => None,
        }
    }

    fn registered_actions(&mut self) -> Vec<proto::ActionInfo> {
        lla_plugin_sdk::manifest_action_infos(include_str!("../plugin.toml"))
    }

    fn run_action(&mut self, action: String, arguments: ActionArguments) -> proto::ActionResponse {
        if action != "inspect" {
            return response::error(format!("unknown action '{action}'"));
        }
        let path = match arguments.path("path") {
            Ok(Some(path)) => path,
            Ok(None) => return response::error("path is required"),
            Err(error) => return response::error(error),
        };
        let multiplier = match arguments.integer("multiplier") {
            Ok(value) => value.unwrap_or(1),
            Err(error) => return response::error(error),
        };
        let size = match std::fs::metadata(&path) {
            Ok(metadata) => metadata.len(),
            Err(error) => return response::error(format!("{}: {error}", path.display())),
        };
        response::value(value::object([
            ("path".to_string(), value::path(path.to_string_lossy())),
            (
                "score".to_string(),
                value::integer(score(size) * multiplier),
            ),
            ("size_class".to_string(), value::string(size_class(size))),
        ]))
    }
}

lla_plugin_sdk::export_plugin!(FileScore);

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn scores_are_log2_of_size() {
        assert_eq!(score(0), 0);
        assert_eq!(score(1024), 10);
    }

    #[test]
    fn classes_change_at_one_kib_and_one_mib() {
        assert_eq!(size_class(1023), "small");
        assert_eq!(size_class(1024), "medium");
        assert_eq!(size_class(1_048_576), "large");
    }
}
```

Each method has one job:

| Method | What it does here |
| --- | --- |
| `decorate_entry` | Sets `score` and `size_class` on regular files. `insert_field` stores a typed value for machine output and a display string for people. |
| `format_field` | Returns the text printed after the name. It runs once per entry, with the name of the current view's format. |
| `registered_actions` | Reports the actions the code handles. Building the list from the manifest keeps the two in step. |
| `run_action` | Receives arguments the host has already validated and returns typed output. The host does the printing. |

`export_plugin!` generates the entrypoint lla looks for. It also validates `plugin.toml` when the crate compiles and embeds the file's exact bytes in the library.

## Run the tests

```bash
cargo test
```

```text
running 2 tests
test tests::classes_change_at_one_kib_and_one_mib ... ok
test tests::scores_are_log2_of_size ... ok

test result: ok. 2 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
```

A manifest mistake stops the build here. Remove the `description` from the `path` argument and the compiler reports it:

```text
error: invalid API v3 plugin.toml: argument 'path' in action 'inspect' needs a description
```

## Install the package

```bash
lla install --dir .
```

On a terminal, lla opens a `Select plugins to install` list with nothing selected, even when it finds one plugin. Press Space to select `file-score`, then Enter. Pressing Enter alone ends with `No plugins selected`.

```text
  ℹ Found plugins: file-score v1.0.0

  ℹ Selected 1 plugin
  ℹ file-score will be built independently
  ✔ Built and installed file_score in 12s
  ✔ Installed file_score  v1.0.0

╭─ Summary ────────────────╮
│   ● Installed (1)        │
│                          │
│       file_score  v1.0.0 │
╰──────────────────────────╯

  ∑  1 installed · 0 failed · 1 total
```

The installer runs `cargo build --release`, copies the library and the manifest into a package directory, and writes a checksum for each file.

```bash
ls ~/.config/lla/plugins/file_score
```

```text
checksums.toml
libfile_score.dylib
plugin.toml
```

The library is `libfile_score.so` on Linux and `file_score.dll` on Windows.

## Run the doctor

```bash
lla plugin doctor
```

```text
Plugin Platform v3 diagnostics
  ✓ ~/.config/lla/plugins
    ✓ file_score v1.0.0 (API 3..=3, checksums + contract verified)
  · /opt/homebrew/lib/lla/plugins (not present)
  · /usr/local/lib/lla/plugins (not present)
  1 plugin artifact(s) checked
```

This is the check that matters. A source install builds and copies the package and never loads it, so a plugin that breaks its contract still installs. The doctor verifies the checksums, loads the library, compares its embedded manifest with the packaged file, compares its actions with the declared ones, and sends it test entries.

To see a failure, delete `registered_actions` from `src/lib.rs` and reinstall. The install succeeds and the doctor exits with status 1:

```text
Plugin Platform v3 diagnostics
  ✓ ~/.config/lla/plugins
    ✗ file_score: manifest/runtime metadata mismatch
  · /opt/homebrew/lib/lla/plugins (not present)
  · /usr/local/lib/lla/plugins (not present)
  1 plugin artifact(s) checked

✗ Plugin Error

  Plugin Platform v3 diagnostics found problems
```

Put the method back, then install and run the doctor again. [Developing plugins](/docs/plugins/developing#diagnose-a-failure) maps each doctor message to its cause.

## Use it in a listing

An installed plugin stays disabled until you enable it.

```bash
lla --enable-plugin file_score
```

```text
.git/
.gitignore [score:3]
Cargo.lock [score:13]
Cargo.toml [score:7]
plugin.toml [score:9]
src/
target/
```

The directories have no score because `decorate_entry` skips them.

<Callout type="note">
`--enable-plugin` writes the plugin to `enabled_plugins` in your config, so it stays on for later runs. Turn it off with `lla --disable-plugin file_score`.
</Callout>

The long view asks the plugin for its `long` format:

```bash
lla -l
```

```text
drwxr-xr-x  288B Nov 04 23:03 you staff .git/
-rw-r--r--    8B Nov 04 23:03 you staff .gitignore score=3 class=small
-rw-r--r-- 14.0K Nov 04 23:03 you staff Cargo.lock score=13 class=medium
-rw-r--r--  155B Nov 04 23:03 you staff Cargo.toml score=7 class=small
-rw-r--r--  961B Nov 04 23:03 you staff plugin.toml score=9 class=small
drwxr-xr-x   96B Nov 04 23:03 you staff src/
drwxr-xr-x  192B Nov 04 23:03 you staff target/
```

Machine output carries the typed values under `plugin`:

```bash
lla --json --pretty plugin.toml
```

```text
  "git_status": null,
  "plugin": {
    "size_class": "small",
    "score": 9
  }
}]
```

## Run the action

```bash
lla plugin run file_score inspect -- plugin.toml
```

```text
{
  "path": "plugin.toml",
  "score": 9,
  "size_class": "small"
}
```

Tokens after `--` belong to the action. Host options such as `--output` go before it.

```bash
lla plugin run file_score inspect --output ndjson -- plugin.toml --multiplier 3
```

```text
{"path":"plugin.toml","score":27,"size_class":"small"}
```

The host validates arguments against the manifest before your code runs. A value above the declared `max` never reaches `run_action`:

```bash
lla plugin run file_score inspect -- plugin.toml --multiplier 11
```

```text
✗ Plugin Error

  argument 'multiplier' is above its maximum
```
