This walkthrough takes about 15 minutes. Run it in a project of your own, ideally a Git repository, and type each command as you go. Your project files stay untouched.

You need lla installed. `lla --version` should print `lla 0.6.6`. If it doesn't, start with [Installation](/docs/about/installation).

## First listing

Run `lla` with no arguments to list the current directory.

```bash
cd ~/project
lla
```

```text
.envrc
.git/
CHANGELOG.md
README.md
docs/
```

Directories end in `/`, and dotfiles are included by default. To list somewhere else, pass a directory, one file, or a `.zip`, `.tar`, `.tar.gz` or `.tgz` archive, as in `lla docs`.

The first run also creates `~/.config/lla/config.toml`. You'll change a setting in it later.

## Long view

Use `-l` when you care about size, date or permissions.

```bash
lla -l
```

```text
-rw-r--r--    10B Dec 09 05:37 you staff .envrc
drwxr-xr-x   416B Nov 04 22:52 you staff .git/
-rw-r--r--  43.8K Oct 07 15:26 you staff CHANGELOG.md
```

<Shot name="view-long" alt="lla -l listing a project with permissions, size, modified time, owner, group and name." />

Add `-s` to sort. Size sorts largest first and date sorts oldest first, and `-r` reverses either one. The second command here puts your most recent changes at the top.

```bash
lla -l -s size
lla -l -s date -r
```

## Tree

Use `-t` to see how a project is laid out. `-d` limits the depth, and the default is 3.

```bash
lla -t -d 2 docs
```

```text
└── docs/
    ├── README.md
    ├── maintainers/
    │   └── releasing.md
    ├── plugins/
    │   └── migration-v3.md
    └── views.md
```

<Shot name="view-tree" alt="lla -t drawing a project's directories and files as a tree." />

Tree view leaves out dot-named files, and `-a` doesn't bring them back. Use `lla --dotfiles-only` to see them.

## Git

Use `-G` to see what changed and who last touched each file.

```bash
lla -G
```

```text
⎇ main ↥origin/main @2daeae36
stage 1  worktree 2  untracked 5
────────────────────────────────────────────────────────────────────────────────────────────────
Status   Name          Commit    Subject                                           Time
────────────────────────────────────────────────────────────────────────────────────────────────
[new]    bookmarks.rs  -         (uncommitted)                                     pending
[clean]  commands/     @b32fdb4  fix: embed MIT license in the CLI                 4 weeks ago
[S:mod]  installer.rs  @32c6cc4  fix(ci): resolve Windows validation failures      3 months ago
[W:mod]  main.rs       @ad7260c  feat(plugins): add batching and persistent ca...  3 months ago
```

<Shot name="view-git" alt="lla -G showing the branch, change counts, and a status, commit, subject, time and author for each entry." />

`[new]` is untracked, `[S:mod]` is modified and staged, and `[W:mod]` is modified in the work tree.

The counts in the header cover the whole repository. A directory row shows `[clean]` even when a file inside it changed, so `cd` into the directory to see that file's status.

## Filtering and search

Use `-f` to narrow a listing by name. A pattern starting with `.` matches an extension, and any other pattern matches part of the name. Use `OR` for alternatives.

```bash
lla -f ".toml OR .md"
```

```text
CHANGELOG.md
Cargo.toml
README.md
rust-toolchain.toml
```

Write patterns in lowercase. Filtering lowercases file names before comparing, so `lla -f readme` finds `README.md` and `lla -f README` finds nothing. Add `-c` to match exact case.

You can also filter by size, as in `lla --size ">10K" --files-only`, or by age. For `--modified`, `">7d"` means changed within the last 7 days.

Use `--search` to look inside files. It needs [ripgrep](https://github.com/BurntSushi/ripgrep) on your `PATH`, and it matches literal text regardless of case. `--no-dotfiles` keeps `.git/` out of the results.

```bash
lla --search "TODO" --no-dotfiles --search-context 0
```

```text
File: README.md [./README.md]
  70 │ lla --search "TODO"     # search file contents
  70 │               ^^^^
```

<Shot name="search" alt="lla --search showing matching lines grouped by file, with the match underlined." />

Run search from the directory you want to search, because a relative directory argument returns nothing in 0.6.6. See [Search file contents](/docs/usage/filtering-search#search-file-contents) for regex patterns.

## A config default

Set a default when you keep typing the same flag. The first command here lists directories first from now on, and the second shows what you've changed from the built-in defaults.

```bash
lla config --set sort.dirs_first true
lla config diff --default
```

```text
Effective overrides compared to built-in defaults:

sort.dirs_first
  default : false
  current : true
  source  : global config
```

For a setting that applies to one project, add a `.lla.toml` file to it with a line such as `default_format = "tree"`. lla uses the nearest one, looking up from the current directory. See [Configuration](/docs/usage/configuration) for every key.

## A first plugin

Plugins add fields to listings, new actions, or both. This command downloads the prebuilt bundle for your platform and asks which plugins to install, with all of them selected. Press Enter to accept.

```bash
lla install
```

Installed plugins stay off until you turn them on. Open the plugin manager, move to `file_hash`, press Space to toggle it, and press Enter to save.

```bash
lla use
```

<Shot name="plugin-manager" alt="lla use listing installed plugins with a checkbox, version and description for each." />

Your listings now include short hashes for each file. Here's `lla -f .toml`:

```text
Cargo.toml
┌─
│ SHA1 b18c9b51
│ SHA256 8a3cd5a8
└─
```

The plugin stays on until you turn it off with `lla --disable-plugin file_hash`. The [first-party plugin catalog](/docs/first-party-plugins/overview) lists the rest.

## A jump bookmark

Bookmark a directory you return to often.

```bash
lla jump --add .
lla jump --list
```

```text
★ ~/project
  ~/project/docs
```

A star marks a bookmark. The other rows are history, which lla records each time you list a directory.

A program can't change your shell's working directory, so `lla jump` only prints the path you pick. Run `lla jump --setup` to add a `j` function that does the `cd`. It goes in `~/.bashrc`, `~/.zshrc` or `~/.config/fish/config.fish`.

Open a new terminal, run `j`, and pick a directory with the arrow keys and Enter.

<Shot name="jump" alt="The lla jump selector with bookmarks marked by a star, followed by recent directories." />
